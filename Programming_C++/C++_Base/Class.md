     3-2 디폴트 생성자: 
     처음에 생성자를 정의하지 않아도 (디폴트)생성자가 호출됨. 디폴트 생성자는 인자를 하나도 가지지 않는 생성자. 클래스에서 사용자가 어떠한 생성자도 명시적으로 정의하지 않았을 경우에 컴파일러가 자동으로 추가해주는 생성자.// 사용자가 어떤 다른 생성자를 추가한 순간 컴파일러는 자동으로 디폴트 생성자를 삽입하지 않는 다는 것을 명심.
    
    e.g.,)//사용자가 직접 디폴트 생성자를 정의한 경우.

    class Date
    {
        private:
        int year,month,day;
        ...
        ...
        Date()
        {
            year=2017;
            month=7;
            day=12;
        }

    }

    int mian()
    {
        Date day1=Date(); //디폴트 생성자에 의해 day1의 year 에는 2012, month 에는 7, day 에는 12
        Date day2;  //디폴트 생성자에 의해 day2의 year 에는 2012, month 에는 7, day 에는 12
        Date day3();// 안됨.디폴트 생성자를 이용해서 초기화 하는 것이 아니라, 리턴값이 Date 이고 인자가 없는 함수 day3 을 정의하게 된 것으로 인식.

    }

    3-3 고민: 컴파일러의 디폴트 생성자를 사용하고 싶을땐 그냥 생성자를 정의하지 않는 방법 밖에 없었음. so 코드를 읽는 사람 입장에선 임마가 생성자를 잊어먹은건지 or 컴파일러의 디폴트 생성자를 use 하고픈지 알길이 없었음.
    >> 해결방법: 생성자의 선언 바로 뒤에 = default 붙이기.(이렇게 하면 클래스의 디폴트 생성자를 정의하라고 컴파일러에게 명시적으로 알려줄수 있음.)

    e.g.,)
    class Test {
    public:
    Test() = default;  // 디폴트 생성자를 정의해라.몸통(중괄화)없는게 특징.
    };

4. 소멸자(destructor): 생성자의 반대. 객체가(stack or heap에서) 사라질때 실행되는 클래스 내부의 함수.

    4-1 형식:
    ~(클래스의 이름);

5. 복사 생성자(copy constructor):일일히 생성자로 생성하는 대신 1개만 생성자로 생성해놓고, 그 한개를 가지고 나머지를 복사 생성 하기 위한 class 내부의 함수.//복사 생성자는 오직 '생성' 시에 호출된다는 것을 명심.


    5-1 형식:
    T(const T& a); // T는 클래스.
    
    e.g.,)
    Photon_Cannon(const Photon_Cannon & pc); // 상수 레퍼런스로 받음으로써 복사 생성자 내부에서 원본을 변경할수 없도록. 

    5-2 주의: 
    Photon_Cannon pc3=pc2;// Photon_Cannon pc3(pc2); 와 동치. 복사생성자.

    Photon_Cannon pc3;
    pc3 = pc2;
    >>>생성자가 1 번 호출되고, pc3 = pc2; 라는 명령.(복사 생성자X.)
    
    5-3 디폴트 복사 생성자:  디폴트 복사 생성자의 경우 기존의 디폴트 생성자와 디폴트 소멸자 두개가 하는 일이 아무 것도 없었던 것과는 달리 실제로 '복사' 를 해줌.// 값만 복제하는 얕은 복사(Shallow Copy).

        5-3-1 디폴트 복사 생성자 주의점: 디폴트 복사 생성자는 얕은 복사만 가능. 따라서 char*가 같은 주소값을 가르킴. 2개으 객체가 delete  될때 이미 해제된 동일한 메모리를 또 해제하려는 시도>런타임 에러발생.

        >>> 대안: 깊은 복사(Deep Copy): 포인터가 가리키는 실제 데이터까지 힙 영역에 새 메모리를 할당하여 독립적으로 복사.
        //즉, 니가 직접 복사 생성자를 코드 해라.
